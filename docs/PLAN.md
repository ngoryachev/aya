# План первой версии

Каждый этап даёт работающую систему. Порядок выбран так, чтобы самое рискованное, цикл решения, проверить раньше всего.

## Этап 0. sdlc на macOS (параллельно, отдельный агент)

См. `HANDOFF-sdlc-macos.md`. Остальные этапы от него не зависят до этапа 4.

## Этап 1. Каркас сервиса

- отдельный сервис на Agent SDK, SQLite;
- сущности из спеки: персона, роль, агент, узел, проект, задача (граф зависимостей), решение;
- лента событий и веб-интерфейс на чтение;
- заимствуем из `sdlc`: запуск сессий, ленту событий, вход по токену, уведомления в Telegram.

Результат: можно завести проект, агентов и персон и видеть ленту.

## Этап 2. Цикл решения на одном агенте

- агент создаёт кандидата в решения с самооценкой;
- автоконтур предлагает классификацию и решение;
- владелец классифицирует, отвечает, подтверждает или правит самооценку;
- решения сохраняются как прецеденты;
- вмешательство: пауза, отмена, правка.

Внешнего мира ещё нет: на всё отвечает владелец. Результат: видно, сколько кандидатов создаёт агент и насколько точна его самооценка.

## Этап 3. Шлюз

- исходящие в Slack от аккаунта владельца с префиксом агента;
- одобрение и правка сообщения, уроки стиля с охватом, руководство по стилю;
- входящие: привязка ответа к агенту и решению по треду;
- карточки персон, утверждение контактов;
- политика исходящего контента, журнал.

Результат: вопрос доходит до живого эксперта и ответ возвращается в решение.

## Этап 4. Работа через sdlc

- входной контроль задачи;
- техлид заводит задачу в `sdlc` и отвечает на чекпоинты;
- ответы на чекпоинты идут через цикл решения.

Результат: задача проходит путь от постановки до PR силами агентов.

## Этап 5. Команда целиком

- роли: ПМ, техлид, архитектор, два разработчика; иерархия;
- Jira: чтение задач, связь с внутренними, запись статусов и комментариев;
- пакеты для живых тестировщиков: ветка, статусы в Jira, сообщение в Slack-канал;
- статус «неактуальна».

Результат: команда ведёт проект, владелец только классифицирует и утверждает.

## Этап 6. Автономия

- статистика совпадений по классам решений, ручная выдача автономии по ступеням;
- снятие обязательного одобрения с классов сообщений;
- ИИ-подмена персоны со списком классов;
- метрики из спеки.
